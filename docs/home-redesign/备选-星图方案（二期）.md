## 0. 一句话

把首页从「两个设备入口」升级为「我家的状态面板」：**一图看家 · 一屏可控 · 一插即入**。

---

## 1. 为什么要改

现状（见 `docs/device-home.png`，代码 `src/pages/home/index.vue`）：

| 问题 | 具体表现 |
| --- | --- |
| 按品类堆卡片 | 第 3、4 类设备接进来只能再堆一张卡，页面会越来越像「入口清单」 |
| 没有实时状态 | 只知道「风扇 0 台」，不知道在不在吹、几档；故事机是否在播也不知道 |
| 关键信息埋得深 | 家长控制要经过 首页 → 故事机 → 家长控制 三层 |
| 首屏空 | 两卡一提示，剩余半屏空白，撑不起「控制中心」的定位 |

核心矛盾：**设备只会变多，而卡片式入口是线性增长的**。改版要解决的不是「再加一张卡」，而是「设备变多时首页仍然只有一屏重点」。

---

## 2. 理念：三层结构 + 一条扩展原则

**三层**（从上到下回答三个问题）

1. **概览层**：家里现在怎么样？——在线几台、谁在运行、今天陪伴多久。
2. **情景层**：我想干什么？——睡眠 / 清凉风 / 听故事，一键跨设备。
3. **设备层**：具体是哪台？——常用 2~4 台直接开关，其余进「全部设备」。

**扩展原则：首页由「能力」拼装，而不是由「品类」堆叠。**

每个设备原型（adapter）声明自己能提供哪些首页能力，首页按能力槽位渲染：

| 能力 | 首页表现 | 例子 |
| --- | --- | --- |
| `metric` | 概览卡里的一格数字 | 温湿度计 →「室内 24°」；故事机 →「今日陪伴 32 分钟」 |
| `live` | 「正在使用」卡片 / 横向卡 | 故事机播放进度、灯亮度、净化器 PM2.5 |
| `quick` | 设备格上的开关 / 档位 | 风扇 2 档、插座通断 |
| `scene` | 被场景调用的动作 | 睡眠场景：关灯 + 故事机音量降到 3 |
| `guard` | 家庭守护行 | 故事机使用时长、内容分级 |

**结果**：接入温湿度计，首页自动多一格温度；没接入就自动隐藏，不留空位。
新品类上线**不需要再改首页布局**——这是这份设计对「后续还有很多设备」的正面回答。

> 图 02 中的「室内 24°C」「PM2.5 32」都是这类能力的示意：真实上线时，没有对应传感器就不显示；一期概览卡实际是「在线设备 / 今日陪伴 / 待接入」。

## 3. 三个方向（图 01）

| | A · 星图中枢 | B · 控制台矩阵 | C · 空间流 |
| --- | --- | --- | --- |
| 强项 | 概念最直接：家是中心、设备是节点，一眼看懂「万物互联」 | 状态与开关一屏完成，设备多了也不失控，最像成熟 IoT 应用 | 最贴近家庭心智：按房间找设备，天然支持「房间级」操作 |
| 代价 | 星图位置有限，超过 6~8 台就要另开列表；节点热区偏小 | 偏工具感，缺少「家」的情绪；容易做得像别的 App | 设备一多页面很长；跨房间的联动（场景）表达弱 |
| 适合 | 品牌记忆点、发布会/首屏 | 日常高频控制 | 家庭共享、长辈使用 |

**结论：不做单选题。**
用 B 的骨架保证可扩展，用 A 的星图做首屏记忆点，把 C 的「房间」变成设备页的分组维度 → 推荐方案。

## 4. 推荐方案

### 4.1 首页（图 02 左）

| 区块 | 内容 | 数据来源 | 点击 / 规则 |
| --- | --- | --- | --- |
| 星图 | 中心「家」+ 内环在线设备 + 外环待接入/离线 | `savedDevices`、`storyDevice` + 连接态 | 点节点进对应控制页；超过 4 台显示「+N」→ 全部设备 |
| 概览卡 | 在线 2/4 · 今日陪伴 32 分钟 · 待接入 2 台 | 聚合快照（能力 `metric`） | 点「待接入」→ 扫描 |
| 快捷场景 | 睡眠 / 清凉风 / 听故事 | 本地 `scenes`（预设 3 个） | 长按进入编辑（二期） |
| 正在播放 | 故事机：标题、进度、音量、暂停 | 故事机 status 帧（已存在） | 无播放时整块隐藏 |
| 常用设备 | 2~4 台，带开关/暂停 | `quick` 能力 | 「全部 4 台 ›」→ 设备页 |
| 家庭守护 | 使用时长 / 内容分级 / 睡眠时段 | status 的 `used`、`limit`、`lock` | 进家长控制 |
| 生态条 | 即将接入：灯 / 净化器 / 温湿度计 / 插座 | 配置常量 | 进设备页「心愿」入口 |

为什么首页只放 4 台：**首页负责「重点」，设备页负责「全部」**。
设备从 2 台到 20 台，首页长度不变，这是这次改版最重要的结构性决定。

### 4.2 全部设备页（图 02 右）

- 顶部：返回 + 标题 + 计数副标题 + 「+」添加入口。
- 筛选：全部 / 按房间 / 待接入。
- 按房间分组网格：每台设备一张状态卡（图标、名称、一行状态、快捷开关）；房间设备数为奇数时用「添加设备」占位，不留空洞。
- 待接入：BLE 扫描结果直接给信号强度与「接入」按钮，绑定流程不跳页。
- 底部：「房间与分组管理」+「即将支持」品类 + 设备心愿入口。

### 4.3 扩展态（图 03 左）

10 台 / 3 个房间时，页面只多了三样东西：

1. 顶部「正在使用」横向卡片（只放运行中的，最多 3~5 个）；
2. 房间可收起：`儿童房 · 3 台 · 2 在线 · 故事机播放中` 一行摘要 + 设备小图标堆叠 + 展开箭头；
3. 「添加新设备」沉到底部。

规则：**展开态房间 ≤ 2 个**，其余默认收起；用户点开某房间时自动收起另一个。避免越用越长。

### 4.4 空态（图 03 右）

第一次打开（无任何设备）：

- 星图只留中心和虚线空节点，文案「把第一台设备接进来，这里就会亮起来」——把「空」设计成「即将点亮」。
- 主 CTA「搜索附近设备」占满宽度；次入口「扫码 / 输入设备码」。
- 「三步开始」+ 支持品类（已支持实心、即将支持虚线），降低首次失败率。
- 扫描无结果 → 同页切换成「没找到？查看配对帮助」，不留死路。

## 5. 视觉规则

### 5.1 星图几何（可参数化实现）

| 项 | 值 |
| --- | --- |
| 画布 | 342 × 178（内容宽 342 = 390 − 2×24） |
| 中心节点 | 56px 白圆 + 2px 蓝色房子描边 + 5px 冷光外圈 |
| 内环 `r=54` | 在线设备，最多 3 个，节点 40px |
| 外环 `r=84` | 离线 / 待接入，最多 4 个，节点 30px 虚线 |
| 角度 | 从 −55° 起，按 **黄金角 137.5°** 递增，天然不重叠 |
| 连线 | 仅在线节点保留，`rgba(156,200,255,.5) → 0` 渐变；离线透明度 8% |
| 超限 | 第 5 台起不再画节点，改为「+N」节点，点击进设备页 |

生产实现建议：**1 张 SVG 背景（base64 内联）+ 绝对定位热区**（比纯 CSS 好维护，也比 canvas 省电）；热区 ≥ 44×44（88rpx）。

### 5.2 色彩与语义

| 语义 | 色值 | 用途 |
| --- | --- | --- |
| 品牌蓝 | `#3b8eff` / 深 `#1f6bff` | 主行动、风扇 |
| 夜蓝 | `#12294e → #0a1830` | 星图背景（仅首页顶部） |
| 故事橙 | `#ff9f43` / 深 `#e8830f` | 故事机、家庭守护 |
| 成功 | `#2ec27e` | 在线节点呼吸点 |
| 待接入 | `#f0a92b` | 扫描结果、待接入 |
| 中性 | `#16202f / #7b8798 / #eaeef5` | 文本 / 次要 / 分割 |

品类色板（新增设备从这里取，避免每接一类就发明一个颜色）：
`蓝 #2f7dff · 橙 #ff9f43 · 紫 #7b6cf6 · 青 #12b3a8 · 绿 #1fae6d · 灰 #93a0b2`

### 5.3 尺寸 token（px → rpx，1px ≈ 1.923rpx）

| 用途 | px | rpx |
| --- | --- | --- |
| 页面左右边距 | 20 | 40 |
| 区块间距 | 18 | 36 |
| 卡片圆角 | 18 / 20 | 36 / 40 |
| 卡片内边距 | 12~14 | 24~28 |
| 主标题 | 22 | 42 |
| 区块标题 | 15 | 28 |
| 正文 | 13 | 25 |
| 状态 / 次要 | 11 | 21 |
| 微标签 | 9.5 | 18 |
| 最小点击热区 | 44 | 88 |
| 卡片阴影 | `0 6px 22px rgba(22,40,72,.07)` | `0 12rpx 44rpx` |

### 5.4 动效

- 在线节点：缩放 1 → 1.06，2.4s 循环；只有在线节点动。
- 连线：虚线 `background-position` 流动 3.5s，`opacity` 0.5 起步。
- 同一屏动画节点 **≤ 4 个**；`onHide` / 系统省电时停掉动画（小程序里用 `useDidHide` 切 class）。
- 不用 `backdrop-filter` / 大范围 `box-shadow` 动画，低端安卓会掉帧。

### 6.3 设备注册表（关键契约）

```ts
// src/devices/types.ts
export type Category = 'fan' | 'story' | 'light' | 'purifier' | 'sensor' | 'plug'
export type Capability = 'metric' | 'live' | 'quick' | 'scene' | 'guard'

export interface DeviceSummary {
  id: string
  category: Category
  name: string
  roomId?: string
  online: boolean
  lastSeen?: number
  stateText: string          // 「运行中 · 2 档」
  progress: number | null    // 0~1，没有就 null
}

export interface DeviceAdapter {
  category: Category
  label: string
  color: string              // 星图节点 / 图标主色
  glyph: string              // iconfont 字形
  route: string              // 点节点去哪
  capabilities: Capability[]
  list(): DeviceSummary[]    // 同步读 storage，不阻塞首屏
}
```

```ts
// src/devices/registry.ts
export const adapters: DeviceAdapter[] = [fanAdapter, storyAdapter]
export const snapshot = computed(() => {
  const devices = adapters.flatMap(a => a.list())
  return {
    devices,
    online: devices.filter(d => d.online).length,
    live: devices.filter(d => d.progress !== null),
    metrics: adapters.flatMap(a => a.metricOf?.(devices) ?? [])
  }
})
```

首页只 import `registry` 和 `snapshot`，**不 import 任何具体品类**。新增设备 = 新增一个 adapter 文件。

## 7. 边界与风险（先说清楚）

1. **BLE 的「在线」不是云端在线**：离开页面连接会断。首页的在线态必须带「最后连接时间」，宁可显示「上次连接 10 分钟前」，也不要假装实时。
2. **故事机状态只有连上才有**：未连接时展示上次摘要 + 灰态，不要显示「播放中」造成误判。
3. **动画成本**：星图只给在线节点做呼吸，最多 4 个；页面隐藏即停。
4. **房间模型要容错**：设备允许没有房间（未分组），删除房间不能删设备。
5. **不要造假数据**：环境数值只能来自真实传感器；没有就整格隐藏（这也是「能力拼装」的意义）。
6. **兼容**：纯 Vue3 + Taro 组件 + WXSS，无新权限、无新依赖；不引入 canvas 星图。
