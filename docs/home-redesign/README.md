## 0. 这一版按你的三条约束重做

| 约束 | 设计动作 |
| --- | --- |
| **没有「家」的概念** | 标题就是「我的设备」。没有家庭、房间、成员、全屋概览；设备是唯一主体 |
| **设备之间还没通讯** | 不做跨设备场景（睡眠/回家/全屋关闭），不做「今日陪伴」这类聚合指标；所有快捷动作都是**单设备**的 |
| **蓝牙一次只能连一台** | 顶部只强调「当前连接的那一台」，其余一律是「未连接 + 上次连接时间」；**「切换连接」变成核心交互**，并配确认弹层 |

第一轮方案（星图、房间、场景）依赖「多台同时在线 + 设备可联动」，这三个前提现在都不成立，所以整套先放下，等条件具备再拿回来做二期。

## 1. 首页结构（04 图 ①）

| 区块 | 内容 | 数据 | 交互 |
| --- | --- | --- | --- |
| 顶栏 | 我的设备 / 已绑定 3 台 · 1 台已连接 / 蓝牙状态 | 绑定列表 + 链路状态 | 蓝牙关闭时变成橙色「蓝牙未开启 · 去开启」 |
| **当前连接卡** | 设备名、MAC、信号、运行状态、已连接时长 | 链路 + 设备状态帧 | 断开 / 进入控制；无连接时变成「回连」卡 |
| **设备矩阵** | 2 列，每台一格：品类图标、名称、已连接/未连接、上次状态、上次连接时间、主动作 | `savedDevices` + `storyDevice` | 点卡片进详情；开关直接控制；未连接显示「连接」 |
| 添加设备 | 矩阵里的一个空格位「＋」 | — | 进扫描 |
| 附近设备 | 扫描到的未绑定设备 + 信号 + 接入 | BLE 扫描结果 | 接入 → 绑定流程 |
| 说明条 | 「同一时间只能连一台」规则 | 常量 | 降低切换时的心理负担 |

为什么是矩阵而不是列表：一屏能放 4~6 台、每台都有独立的开关位、设备变多只是往下滚，结构不变；也不需要为「品类」重新设计入口。

排序规则：**已连接置顶 → 按 `lastSeen` 倒序**。用户最常用的设备永远在前两格。

## 2. 连接状态机（这次设计的核心）

| 状态 | 顶栏 | 当前连接卡 | 设备矩阵 | 可执行 |
| --- | --- | --- | --- | --- |
| 蓝牙关闭 | 橙色「未开启」 | 「请先开启蓝牙」+ 去设置 | 全部灰态 | 打开蓝牙 |
| 空闲 | 蓝牙已开启 | 「未连接」+ 回连 CTA | 各自「连接」 | 连接 / 扫描 |
| 扫描中 | 蓝牙已开启 | 不变 | 不变 | 停止扫描 |
| 连接中 | 「正在连接 风扇…」 | 骨架 + 取消 | 目标卡「连接中…」，其余禁用 | 取消 |
| 已连接 | 「1 台已连接」 | 完整控制卡 | 目标卡高亮，其余「连接」 | 断开 / 控制 / 切换 |
| 切换中 | 「正在切换…」 | 先回到「未连接」再进入「连接中」 | A 变未连接，B 连接中 | 不可取消（≤3s） |
| 失败 | 恢复上一状态 | 错误原因 + 重试 | 目标卡「重试」 | 重试 / 换设备 |

必须守住的三条：

1. **同一时刻只有一个 connected**：连接 B 之前先 `disconnect(A)`，全部走同一个连接管理器，不允许两个模块各自持有链路。
2. **连接中全局上锁**：连点、连着扫、边连边切都要拦住；否则 BLE 层会返回 `10003/10006` 之类的错误。
3. **断开只改状态，不删设备**：`lastSeen` 记下时间，矩阵靠它排序和展示「上次连接 2 天前」。

---

## 3. 切换连接弹层（04 图 ③）

- **出现时机**：已连接 A，点 B 的「连接」。
- **内容**：A → B 的对照、单连接说明、「断开后设备会保持当前运行状态」。
- **按钮**：取消 / 断开并连接（主）。
- **不出现**：空闲状态下直接连接；点当前已连接的设备直接进详情。
- **故事机**：连接后还需要家长授权，授权流程放在「连上之后」，不要塞进这个弹层（否则用户以为授权失败）。

弹层文案的落点是让用户放心：**掉线 ≠ 设备停了**，风扇还会继续转，只是暂时不能调。

## 6. 数据与代码落点

### 6.1 现状（已核对）

- `src/utils/ble.ts`：风扇侧只有一个 `connectedDeviceId`，本来就是单连接。
- `src/utils/storyBle.ts`：故事机是**另一套连接器**，自己也持有一个 `deviceId`。
- 两者之间没有互斥 → 先连风扇再连故事机，会同时占用两条链路（或在部分机型上直接失败）。**这是当前最需要补的一层。**

### 6.2 新增统一连接层 `src/utils/link.ts`

```ts
export type LinkKind = 'fan' | 'story'
export type LinkStatus = 'off' | 'idle' | 'scanning' | 'connecting' | 'connected' | 'switching' | 'error'

export interface LinkSnapshot {
  status: LinkStatus
  deviceId?: string
  kind?: LinkKind
  since?: number
  error?: string
}

let state: LinkSnapshot = { status: 'idle' }
const listeners = new Set<(s: LinkSnapshot) => void>()

export function subscribe(fn: (s: LinkSnapshot) => void) {
  listeners.add(fn)
  fn(state)
  return () => listeners.delete(fn)
}

export async function connect(id: string, kind: LinkKind) {
  if (state.status === 'connecting' || state.status === 'switching') return false
  if (state.status === 'connected' && state.deviceId !== id) {
    state = { ...state, status: 'switching' }
    emit()
    await disconnect()                 // 关键：先断开
    await sleep(300)                   // 部分安卓立刻重连会失败
  }
  state = { status: 'connecting', deviceId: id, kind }
  emit()
  try {
    const ok = kind === 'fan'
      ? await bleManager.connect(id)
      : await storyBle.connect(id).then(() => true)
    state = ok
      ? { status: 'connected', deviceId: id, kind, since: Date.now() }
      : { ...state, status: 'error', error: '连接失败，请靠近设备重试' }
  } catch (e) {
    state = { ...state, status: 'error', error: '连接被拒绝或设备已被占用' }
  }
  emit()
  return state.status === 'connected'
}
```

配套：

- `onBLEConnectionStateChange` 监听被动断线 → `status = 'idle'` + toast「风扇已断开」。
- 连接前 `stopBluetoothDevicesDiscovery()`，扫描与连接不要并发。
- `lastSeen` / `lastUsed` 写本地 storage，供矩阵排序与「上次连接 x 天前」。

### 与设计稿的差异（都是数据或平台原因）

1. **不显示实时 RSSI**：BLE 连接后拿不到信号值，卡片副标题改为设备型号 / 功率。
2. **风速用百分比**：固件协议就是 `M=<mode>&P=<0-100>`，没有「档」，所以显示「风速 50%」而不是「2 档」。
3. **附近设备只做发现**：风扇可直接接入；故事机需要绑定码 + 家长授权，点「接入」回到故事机页完成。
4. **操作菜单用系统 ActionSheet**：长按弹「重命名 / 删除设备」，比自绘菜单更稳。
5. **矩阵目前全量展示**：设备超过 6 台时建议只放常用 6 台 + 「全部设备」，见下一节。

### 怎么验

1. 微信开发者工具导入本仓库，`npm run build:weapp` 后打开首页。
2. 连一台风扇：卡片出现「运行中」，矩阵里该格变蓝并置顶，开关可直接发指令。
3. 再点故事机「连接」：弹「切换连接」，确认后风扇断开、故事机连上（需授权则跳故事机页）。
4. 长按任意设备：重命名（可重名）、删除。
5. 关掉设备电源：1~2s 内首页回到「未连接」，并提示已断开。

## 8. 后续（P1）

1. **设备超过 6 台**：首页只留常用 6 台 + 「全部设备」页（现在的矩阵是全量）。
2. **品类识别**：附近设备目前按 `StoryBox-` 前缀判断故事机，后续读广播的 manufacturerData 更稳。
3. **失败态细分**：距离远 / 被别的手机占用 / 未授权，现在统一一句「连接失败」。
4. **家长控制角标**：故事机卡片右上角加「护」标记，进详情再做授权。
5. **重命名入口**：从长按改成矩阵右上角「管理」模式，发现性更好。
